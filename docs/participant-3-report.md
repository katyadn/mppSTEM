## Моя зона

`Client.Core`, `Client.Maui`, `tests/Microclimate.Client.Tests`, `deploy/`, `.github/`, solution-конфігурації та документація. ## Що показати на захисті

1. Запустити API й MAUI, показати правильну та неправильну спробу входу. Пояснити: login видає access token, auth/me підтверджує профіль; пароль не зберігається.
2. Відкрити огляд. Показати останні виміри, їхній час і серверну оцінку комфорту. Пояснити різницю між відсутністю даних та числом 0.
3. Відкрити кімнату, змінити метрику й період. Показати графік, розриви, min/avg/max і значення точки. Час на екрані місцевий; запити та серверні інтервали — UTC.
4. У ролі Operator змінити поріг. Спочатку ввести неправильний порядок і показати валідацію, потім зберегти правильні межі. Viewer має лише перегляд; остаточне рішення приймає API.
5. Надіслати синтетичний вимір через симулятор або локальний smoke. Показати оновлення без кнопки: SignalR сповіщає про зміну, клієнт перечитує істинний стан через HTTP. Коли хаб недоступний — повідомлення про стан і перевірка кожні 30 секунд.
6. Відкрити сповіщення, застосувати фільтр і підтвердити відкриту тривогу. Перейти з неї до кімнати.
7. У налаштуваннях змінити тему, показати адресу API та стан збереження сесії. Вийти: сесія очищена, канал подій закритий.
8. Показати код, тести та GitHub Actions. Відрізняти успіх збірки від реального запуску UI і не приписувати собі серверний код інших учасників.

## Метапрограмування

CommunityToolkit.Mvvm генерує властивості та команди з атрибутів; System.Text.Json генерує JSON-метадані; XAML `x:DataType` перевіряє прив'язки під час компіляції; xUnit `[Theory]` перевіряє набори крайових випадків. Перевага — менше повторюваного коду, обмеження — згенерований результат і контракти все одно потребують перевірки.

У реалізації #76 використано Codex для коду, тестів, документації й автоматизованих UI-перевірок. Це задекларовано в `META-USAGE.md`; текст звіту є підготовленим матеріалом, а не заявою, що людина вже виконала захист або рев'ю.
