# Метапрограмування та використані інструменти

У проєкті використовувалися генератори й ШІ-асистенти для коду, тестів та документації. Нижче збережено розподіл робіт із записів учасників; git-автор коміту не доводить ручного написання кожного рядка. Фактичні результати запусків — у [звіті перевірок](docs/verification.md).

## Учасник 1

Інструмент: Claude Code у Claude для Windows; .NET CLI, GitHub CLI, draw.io MCP. Запити: структура й розподіл проєкту, домен, інфраструктура з лабораторної роботи, перевірка DRY/SOLID, сумісність модулів і конфлікти.

З допомогою асистента створювалися Domain, порти Application, Infrastructure/міграції, тести, схема БД, специфікації аналітики й симулятора. Доменні тести коригувалися разом із моделлю. Таблиця аналітики описує продуктові межі з коду; нормативне обґрунтування потребує окремої перевірки.

## Учасник 2

Інструмент, зазначений учасником: Antigravity / Gemini; VS Code / Rider та .NET CLI. Запити: DTO, REST API, JWT/DeviceKey, SignalR, ProblemDetails, інтеграційні тести й документація.

Асистент використовувався для специфікацій, контрактів, API-хоста, контролерів та тестів WebApplicationFactory. Описи API, безпеки й realtime звірено з кодом у #80: вилучено твердження про відсутні маршрути, refresh-сховище й тести. OpenAPI формується із метаданих контролерів; вимірювання переваги cold-start не виконувалось.

## Учасник 3

Інструмент: OpenAI Codex; Rider, .NET CLI, GitHub CLI; для нативних перевірок — XcodeBuildMCP і керування UI. Запити: клієнтські сценарії й MVVM, сесії, HTTP/SignalR, графік і пороги, CI/Compose, тести та матеріали до захисту.

З допомогою Codex реалізовано й доповнено Client.Core/Client.Maui, клієнтські тести, CI, deploy та документацію. У #76 додано пороги, latest/comfort, живі оновлення, тему, інтерактивний графік і перевірки Android/PostgreSQL; для узгодження UI застосовано impeccable. У #80 видалено невикористані реалізації API, скорочено коментарі й документацію, уніфіковано формат C#.

Codex також звірив рубрику з історією GitHub, підготував навчальні питання й тренувальний patch. Офіційного банку питань не було надано. Нативні прогони Mac/iOS виконані автоматизовано; Windows/Android підтверджені збірками, не ручним UI-прогоном. Матеріали не засвідчують особистого усного захисту або самостійної репетиції учасника.

## Механізми генерації

| Механізм | Де застосовано | Користь і межі |
|---|---|---|
| CommunityToolkit.Mvvm | Client.Core/ViewModels | Властивості й команди з атрибутів; потрібні partial-класи та правильні XAML-прив'язки |
| System.Text.Json source generator | ClientJsonContext | Метадані DTO під час компіляції; новий тип слід зареєструвати |
| XAML compiled bindings | `x:DataType` у MAUI | Перевірка binding під час збірки; не перевіряє вигляд і поведінку екрана |
| C# records, атрибути API | Contracts, контролери | Скорочення DTO і декларативна маршрутизація; атрибути відповідей потребують звірки з поведінкою |
| `dotnet ef` | Infrastructure/Migrations | Окремі міграції SQLite/PostgreSQL; DDL потребує перегляду й інтеграційного запуску |
| xUnit Theory/InlineData/MemberData | Тестові проєкти | Спільний тест для набору входів; якість залежить від обраних випадків |
| Mermaid | Схема БД, рішення | Діаграми версіонуються з кодом; не доводять відповідності реалізації |

Згенерований код проходить строгий build і тести, але вони не доводять відсутності всіх дефектів. [Відомі обмеження](docs/known-limitations.md) зберігаються окремо; людське рев'ю та розуміння власного коду залишаються частиною захисту.
