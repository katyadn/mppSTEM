# Правила внеску

Кожна задача починається з issue з критеріями готовності, відповідальним учасником і дедлайном. Зауваження викладача оформлюємо шаблоном `review-feedback` та виправляємо до наступного чекпоінту.

## Гілки та коміти

`main` — інтеграційна гілка. Зміни вносимо лише через PR: `feature/<issue>-<name>` для задач або `fix/<issue>-<name>` для виправлень. Назви гілок та ідентифікатори англійською, документація українською.

Коміти відповідають Conventional Commits і містять номер issue, наприклад: `chore: add solution skeleton (#1)` або `fix: correct navigation route (#5)`. Коміт має описувати логічний крок; потрібен щонайменше один змістовний коміт на тиждень від кожного учасника.

Перед PR виконайте `dotnet build Microclimate.Ci.slnf -c Release` і `dotnet test Microclimate.Ci.slnf -c Release`; для клієнта — також платформну збірку. Не вимикайте перевірки, щоб приховати проблему. Задекларуйте шаблони, generators та допомогу ШІ у своєму розділі META-USAGE.md.

## Рев’ю

Рев’ю відбувається по колу **1→2→3→1**: Учасник 1 перевіряє зміни Учасника 2, Учасник 2 — Учасника 3, Учасник 3 — Учасника 1. Каркас, який зачіпає всіх, додатково переглядають інші учасники.

Результативне рев’ю: рев’юер знаходить суттєву проблему або обґрунтовує покращення; автор виправляє; рев’юер повторно перевіряє результат. Косметичні коментарі самі по собі не зараховуються. Людина зливає PR після змістовного рев’ю й зелених CI jobs.

Початкові PR Етапу 0 залежать один від одного та націлені на main. Переглядайте A→B→C→D→E→F→G; застосовуйте **Create a merge commit**, щоб зберегти спільних предків і скоротити diff наступного PR після попереднього merge. Для подальших незалежних задач створюйте гілки від актуального main.

## Дедлайни та зони

Якщо задача затримується, оновіть issue з причиною та новою датою **до поточного дедлайну** (критерій B2). Учасники не реалізують код чужих зон без погодження; межі описані у `docs/responsibility-zones.md`.

Адміністратор репозиторію має налаштувати захист main: ≥1 PR approval та required check `build-test` (рекомендовано також `maui-build`). Наявність документа не означає, що ці налаштування вже ввімкнені.
